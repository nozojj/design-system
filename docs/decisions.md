# 設計判断の記録

部品を作るときに「なぜこの方法にしたか」を残すメモ。1つの判断につき、決めたこと・理由・他の案・弱点を数行ずつ書く。

## AsymGrid：左右反転は CSS だけで行う

- 決めたこと：`largeSide="end"` のときは、CSS の `grid-column` で大きい枠を右の列に置く。HTML の並び順は変えない。
- 理由：HTML の順番は、スクリーンリーダーが読み上げる順番と Tab キーで移動する順番になる。見た目の都合で変えると、目で見ていない人にとって意味の順番が崩れる。「大きい枠＝主役が先」という順番を、どちらの向きでも同じに保ちたかった。
- 他の案：
  - CSS の `order` で並びを入れ替える → 見た目だけが変わり、読み上げ順とずれる。どこがずれているかがコードから見えにくい。
  - `largeSide` に合わせて JSX の並びそのものを入れ替える → 見た目と読み上げ順はそろうが、主役が後ろに回ってしまう。部品の中に並べ替えの処理が必要になる。
- 弱点：見た目の順番（左 → 右）と、読み上げや Tab の順番（主役が先）が一致しない。目で見ながらキーボードで操作する人は、フォーカスが右から左へ飛ぶように見える。今の Card はフォーカスできる要素を持たないので影響は小さいが、中にリンクやボタンを入れるときは注意が必要。

## AsymGrid：end のときは `grid-auto-flow: dense` を付ける

- 決めたこと：`largeSide="end"` のときだけ、グリッドに `grid-auto-flow: dense` を付ける。start のときは付けない。
- 理由：end では大きい枠に `grid-column: 2` だけを指定している。ブラウザーの自動配置は、ふだんは前に戻らずに先へ先へと置いていく。そのため、大きい枠を右の列に置いたあと、次の子は左上の空きに戻れず、左上のマスが空いてしまった（高さ0の行ができて、Oak が gap の分だけ下がり、Halden が Ash の下端まで伸びない）。dense を付けると、自動配置が前の空きに戻って埋めてくれる。
- 他の案：
  - 大きい枠に行の位置も指定する（例：`grid-row: 1 / span 2`）→ 確実に左上から並ぶが、小さい子の数に合わせて行数を書く必要がある。子の数が変わると崩れる。
  - グリッドに `direction: rtl` を付けて列の向きを逆にする → 並べ方は start と同じで済むが、中の文字の向きまで変わってしまうので、子の側で元に戻す必要がある。
- 弱点：dense は後ろの子を前の空きに詰めることがあるので、見た目の順番が HTML の順番とずれる場合がある。今は小さい子がすべて同じ大きさなので、埋まるのは左上の1マスだけ。大きさの違う子が混ざると、思わぬ順番に並ぶことがある。

## AsymGrid：画面の幅ではなく、置かれた場所の幅で組み替える

- 決めたこと：2列 ⇔ 狭い並びの切り替えは、メディアクエリではなくコンテナクエリ（`@container`）で行う。幅を測るために外側の箱 `ds-asym-grid-container` を足し、グリッド本体はその中に置く。`className` / `ref` / 残りの props は内側（グリッド本体）に渡し、外側は幅を測るためだけに使う。
- 理由：AsymGrid は Composition の部品なので、ページ全体だけでなく、狭いサイドバーや Card の中にも置かれうる。部品が気にするべきなのは画面の幅ではなく、自分が使える幅。また、コンテナクエリが測れるのは「外側の箱」の幅で、自分の幅を見て自分の列を変えることはできない。そのため、測るための箱を外側に足した。
- 他の案：
  - メディアクエリ → 画面が広いと、狭いサイドバーの中でも2列のままになり、細い列がつぶれる。
  - JS（ResizeObserver）で幅を測ってクラスを切り替える → 細かく制御できるが、JS の処理が増え、最初の表示で一瞬崩れることがある。「CSS Grid だけで作り、JS の状態は持たない」という方針にも合わない。
  - 外側の箱を作らず、使う人に `container-type` 付きの親を用意してもらう → 箱は増えないが、付け忘れると切り替わらない。
- 弱点：
  - 箱が1つ増える。`className` は内側に付くので、外側の余白や幅を変えたいときに、思った箱に効かないことがある。
  - `container-type: inline-size` を付けた箱は、中身の幅で自分の幅が決まらなくなる。横並びの flex の中などに幅を指定せずに置くと、幅が 0 に縮むことがある。

## AsymGrid：48rem を境に、狭いときを基本にして書く

- 決めたこと：切り替えの境目は 48rem。CSS は狭いときの並びを基本に書き、`@container (width >= 48rem)` の中で広いときの並びに上書きする。
- 理由：
  - 基本の文字サイズ 16px なら 48rem は 768px で、3:1 のとき細い列は約190px になる。これより狭いと、細い列の中身が窮屈になる。
  - rem にしたので、文字を大きくしている人（例：24px なら 1152px）には早めに狭い並びになり、大きな文字が細い列に詰め込まれない。
  - 狭いときを基本にすると、end のルールは広いときにしか存在しない。狭いときに end のルールを打ち消す必要がなく、詳細度の勝負をしなくて済む。
- 他の案：
  - px で決める → 計算は分かりやすいが、文字の大きさに合わせて切り替わらない。
  - 広いときを基本にする → 狭いときに end のルールを打ち消す必要があり、セレクターを強くする必要が出る。
- 弱点：48rem は 3:1 の細い列を基準にした1つの数字で、3:2 や 2:1 でも同じ境目を使っている。中身（長い英単語や大きな画像など）によっては、もっと早く切り替えたほうがいい場合もある。使う人が境目を変える方法は、今は用意していない。

## AsymGrid：列の幅を `minmax(0, Nfr)` で指定する

- 決めたこと：列を `2fr 1fr` ではなく `minmax(0, 2fr) minmax(0, 1fr)` のように書く。
- 理由：`fr` だけの列は、中身の一番小さい幅より細くならない。そのため、長い英単語や大きな画像が入ると列が広がり、2:1 の比率が崩れる。`minmax(0, …)` で列の一番小さい幅を 0 にすると、中身に関係なく比率どおりに分けられる。
- 他の案：
  - 子の側に `min-width: 0` を付ける → 同じ効果が出るが、AsymGrid.Item すべてに付ける必要があり、付け忘れやすい。
  - 何もせず `fr` のままにする → 中身は必ず収まるが、比率が守られず「非対称のグリッド」という部品の目的が崩れる。
- 弱点：列が中身より細くなれるので、入りきらない中身（長い英単語や大きな画像）は列からはみ出すことがある。中身の側で折り返し（`overflow-wrap`）や `max-width: 100%` などの対策が必要になる。
